# 编写文档

改 `docs` 中的文档时读这一页：文档写给谁、写什么、页面和小节的结构、篇幅的预算。

## 读者

- **AI 编程助手是主要的读者。** 在 Tenon 项目中，它用 MCP 工具 `tenon_search_docs` 按小节检索 `.tenon/docs`，用 `tenon_read_doc` 读一页的目录或其中一节，或者用 `rg` 搜索。它一次只读一两节，读进来的每一个字都占它的上下文。
- **其次是 Go 初级工程师。** 他手边有 AI，通用的概念和 Go 的写法会去问 AI；他从文档中要的是 Tenon 怎么用。

所以文档只写 Tenon 自己的东西，写得短，每一节单独读也能用。

## 写什么

写：

- 用哪个包、哪个函数，代码放在项目的哪里，在入口中怎样装配；
- 最小的完整例子；
- 必须遵守的规则和违反它的后果；
- 配置项；
- 线路上的行为：[客户端协议](../docs/http/protocol.md)和 [RPC 协议](../docs/rpc/protocol.md)是给其他语言实现客户端的规范，保持完整。

不写：

- **通用概念和 Go 的写法**：缓存命中、事务、JWT、CSRF、`context`、泛型这些，读者自己知道或者去问 AI。用到时最多一句话说明它在这里起什么作用。
- **逐行讲解代码**：说明写在代码的注释中，代码之后最多列几条要点。
- **API 参考**：函数签名、参数和返回值以 godoc 为准，读者用 `go doc github.com/go-tenon/tenon/<包>` 查。导出的标识符都有注释，由 golangci-lint 的 revive 检查。页面中只出现例子用到的函数。
- **框架内部的实现**：只写对应用有影响的结论，例如“用 cookie 认证的写请求必须来自同源页面，否则返回 403”。改框架时才需要知道的机制写在 `contributing` 或代码注释中。
- **和正文重复的常见问题**：一个坑写在用到它的那一节中。
- **只对人有用的引导**：阅读顺序、“阅读前需要了解”、“下一步读什么”、页内目录。`tenon_read_doc` 和 GitHub 自动给出目录。
- 和其他框架的比较。

## 目录与页面

`docs` 按主题分目录。与入口无关的部分（`concepts`、`general`、`database`、`libraries`、`features`、`security`、`ai`）和各个入口（`http`、`rpc`、`background`、`frontend`、`clients`）分开放：讲业务动作、错误、认证这类共用的部分时，不假设调用来自 HTTP；某个入口特有的写法放在这个入口的目录中。新增入口时，新建一个与 `http` 平级的目录。

- **一个主题一页。** 同一个包的用法写在同一页中，不按篇幅拆页；页面长没有关系，控制的是每一节的长度。
- **[docs/README.md](../docs/README.md) 是唯一的目录**，每页一行，按主题分组，开头一句话给初学者指出阅读顺序。新增、合并或删除页面时更新它，再在仓库根目录运行 `go run ./internal/llmstxt/gen` 重新生成 `llms.txt`。
- 新增的包同时加入[框架包一览](../docs/concepts/structure.md#framework-packages)。

## 每一页的结构

```markdown
# 缓存

用 Memcached 缓存查询结果：先读缓存，没有时查库并写回。

包：`cache`。

<a id="example"></a>
## 示例

（最小的完整例子）

<a id="remember"></a>
## 用 `Remember` 缓存查询结果

（一个任务：代码，加上几条要点和规则）

<a id="config"></a>
## 配置
```

- **开头**：一两句话说明这一页讲什么。下一段写“包：”，列出这一页讲的框架包：Go 包的路径相对于模块，前端包写 npm 名称，例如 `` 包：`login`、`login/passkey`。``、`` 包：`@go-tenon/ui`。``；没有对应的包时省略。跨小节的硬规则（最多两三条）紧接着写在这里。
- **示例**：第一节是最小的完整例子，能直接复制使用。以 `package` 开头的代码块是完整文件，`doctest` 单独编译它；其余片段只用于阅读。
- **任务**：之后每一节讲一个任务。标题写任务和 API 的名字，用 AI 会搜索的词，例如“用 `Remember` 缓存查询结果”“提交事务之后删除缓存”。
- **规则**写在用到它的那一节中，一句话加上理由，例如“命中缓存之后仍要检查权限：缓存中的数据不带权限。”
- **配置**：配置项集中在一节中，用 YAML 示例加行尾注释写出作用和默认值。

## 小节

读者一次只读一节，所以每一节都要单独读得懂：

- 片段中的变量在这一节中交代来源，例如“`db` 是入口打开的 `*bun.DB`”。不写“如上所述”“前面的例子”；要用另一节的内容时给出链接。
- 每一节（从一个锚点到下一个锚点）不超过 3000 个字符。超过时按任务拆成几节，不拆页。
- 每个 `##`、`###` 标题的前一行是锚点 `<a id="..."></a>`，锚点用英文短语。技能、`devmcp` 的测试和其他页面都引用锚点，改名时一起改，`doclinks` 和 `TestSkillReferences` 会检查。
- 同一个概念只用一个词，用 AI 会搜索的那个：对输入的检查叫“校验”，“验证”只用于身份（验证码、验证邮箱）；用“接口”，不用“端点”指 HTTP 接口。

## 写法

- **直述。** 直接说明它是什么、做什么，不用否定或对比来描述。句子短，一句只说一件事。
- **代码**：一个代码块只说明一件事，运行结果写在注释中。
- **表格**只用于对照多种情况，例如“校验器返回什么 → 响应的状态码”。
- **提示块**只用两种：`> [!IMPORTANT]` 必须遵守的约定，`> [!WARNING]` 安全问题和后果严重的坑。其余内容写成正文。
- **链接**：上游库的用法链接到它的文档，不在这里重复；通用概念不加链接。

[入门教程](../docs/tutorial/01-project.md)给初级工程师从头做一遍：每章只有命令、代码和一两句说明，不解释通用概念。`cmd/tenon` 的 `TestTutorial` 按章节执行带 `title` 的完整文件和正文中的命令，改教程的代码时在本地用 `TENON_SCAFFOLD_TEST=1` 运行它。

## 预算

`internal/checks/docbudget` 检查这些上限。AI 编程助手每次会话都会读到 `AGENTS.md`、技能的描述和文档目录，它们越短越好；技能的正文和文档的小节在用到时才读。

| 内容 | 上限（字符） |
| --- | --- |
| 项目 `AGENTS.md` 的模板 | 4500 |
| 技能的 `description` | 200 |
| 技能的 `SKILL.md` 全文 | 3500 |
| `docs/README.md` | 5000 |
| 文档中的每一节 | 3000 |

## 检索

`cmd/tenon/internal/devmcp` 的 `TestSearchDocs` 是文档检索的回归用例：每一条是 AI 编程助手常用的查询和应该排在前三的页面或小节。改了标题、措辞或者拆合了页面之后运行它；新增一页时，为它加一两条查询。
