# 界面文字

项目支持的语言在 `tenon.json` 的 `languages` 中声明，第一项是源语言（默认 `["zh-CN"]`）。单语言项目直接在页面代码中写文字；配置两种及以上语言时启用多语言模式：前端界面文字写在 `locales/<前端>.<语言>.yaml` 中并用 `useT` 取出。服务端的错误提示见[本地化](../general/localization.md)。

包：`@go-tenon/client`、`@go-tenon/ui`。

<a id="single-language"></a>
## 单语言项目（默认）

`tenon init` 默认生成单语言项目（源语言为 `zh-CN`），不创建 `locales/`、`src/i18n.ts` 和 `messages.gen.ts`：

- 页面文字和路由菜单的 `staticData.title` 直接写在代码中，例如 `<Button>添加</Button>`、`staticData: { title: "待办" }`。
- `createApp` 不传 `i18n`，`@go-tenon/ui` 组件按 `language`（默认 `"zh-CN"`）显示内置文字；需要覆盖个别内置组件文字时传 `uiMessages`：

```tsx title="apps/web/src/router.tsx"
const app = createApp({
  id: "web",
  routeTree,
  language: "zh-CN", // 纯英文等非中文项目改为 "en"
  uiMessages: { "tenon.table.empty": "还没有内容" },
})
```

- `createKit(api, { language: "zh-CN" })` 直接固定显示语言；`tenon check` 默认不运行写死汉字的 `text` 检查。
- 之后需要加第二种语言时，运行 `go tool tenon add language en`：它把 `en` 加入 `tenon.json`、生成翻译文件骨架与 `src/i18n.ts`、切换 AI 约定并开启 `text` 检查，再用 `go tool tenon check --only text,errors` 列出所有待抽离的前端文字与待翻译的错误码。

<a id="example"></a>
## 多语言示例

建项目时用 `tenon init --languages zh-CN,en`，或在已有项目中运行 `go tool tenon add language en` 启用多语言。翻译文件放在项目的 `locales` 目录中，每个前端每种语言一个文件，文件名是 `<前端>.<语言>.yaml`，写法与服务端的翻译文件相同：

```yaml
# locales/web.zh-CN.yaml
nav.inbox: 收件箱
inbox.empty: 没有会话
inbox.waiting: "{{.count}} 个会话等待回复"
```

```yaml
# locales/web.en.yaml
nav.inbox: Inbox
inbox.empty: No conversations
inbox.waiting:
  one: "{{.count}} conversation waiting"
  other: "{{.count}} conversations waiting"
```

`tenon generate`（`tenon dev` 中自动运行）把它们生成为 `apps/web/src/messages.gen.ts`。前端的 `src/i18n.ts` 用它创建翻译，交给 `createApp`、生成的客户端和 `createKit`：

```ts title="apps/web/src/i18n.ts"
import { createI18n } from "@go-tenon/client"
import { messages } from "./messages.gen"

export const i18n = createI18n({ messages, defaultLanguage: "zh-CN" })
```

```ts title="apps/web/src/api.ts"
export const api = createClient({ baseURL: "/api", fetch: apiFetch, headers: i18n.headers })
export const kit = createKit(api, { scope: session.scope, language: i18n.language })
```

```tsx title="apps/web/src/router.tsx"
const app = createApp({ id: "web", routeTree, session, i18n /* , … */ })
```

页面用 `useT` 取文字，菜单的标题写消息 ID：

```tsx
export const Route = createFileRoute("/_app/inbox")({
  staticData: { title: "nav.inbox", icon: "inbox" },
  component: Inbox,
})

function Inbox() {
  const t = useT()
  return <Text>{t("inbox.waiting", { count: 3 })}</Text>
}
```

<a id="messages"></a>
## 翻译文件与 `messages.gen.ts`

- 各语言的消息不一致时，`tenon generate` 提示哪个文件缺少哪些消息；没有前端翻译文件时跳过生成。
- 占位符是 `{{.name}}`，取自 `t` 的第二个参数；复数按 `count` 在 `zero`、`one`、`two`、`few`、`many`、`other` 中选择，没有对应的形式时用 `other`。
- `messages.gen.ts` 登记了全部消息 ID，`useT` 只接受其中的 ID，写错时类型检查报错。它和 `routeTree.gen.ts` 一样提交，不手改。
- 服务端的 `i18n.New` 同样加载这些文件，发邮件、通知时可以用同一条消息。各前端和服务端的消息共用一个 ID 空间，ID 按模块起名，例如 `inbox.empty`。

<a id="language"></a>
## 当前语言：`setLanguage`、`Accept-Language`

- 可以选的语言是 `defaultLanguage` 和翻译文件中有的语言。组件内置的英文只在应用也有英文时使用：应用只有简体中文时，界面整个是简体中文。
- 初始语言按浏览器的语言偏好在这些语言中选择，匹配不到时是 `defaultLanguage`。
- 登录后按用户的设置切换：`i18n.setLanguage(me.language)`。传入的语言没有消息时，依次用同一主语言的语言和默认语言。
- 切换后，`useT`、菜单、面包屑、标签页、`@go-tenon/ui` 组件和资源页面的字段名、枚举一起变成新的语言，`<html lang>` 随之变化，请求带上新的 `Accept-Language`，服务端的错误提示也是这种语言。
- `LanguageMenu` 是语言菜单：`<LanguageMenu languages={…} value={useLanguage()} onChange={(v) => i18n.setLanguage(v)} />`。

<a id="ui-messages"></a>
## 组件的文字：覆盖内置消息

`@go-tenon/ui` 内置组件文字的简体中文和英文，消息 ID 以 `tenon.` 开头，列在 `@go-tenon/ui` 的 `uiMessages` 中，例如 `tenon.common.save`、`tenon.table.empty`。

- 多语言应用在翻译文件中写同一个 ID 覆盖它：

```yaml
# locales/web.zh-CN.yaml
tenon.table.empty: 还没有内容
```

- 单语言应用直接传给 `createApp` 的 `uiMessages` 选项。

<a id="check-text"></a>
## 检查写死的文字：`tenon check`

`tenon.json` 配置两种及以上 `languages` 时，`go tool tenon check` 自动运行 `text` 检查，列出各前端 `src` 中注释以外写着汉字的行，有时以非零状态退出，适合放进 CI。单语言项目默认跳过它，也可以用 `go tool tenon check --only text` 显式运行。生成的文件（`*.gen.ts`）和测试不检查；给开发者看的中文（例如 `console.warn`）在这一行加上注释 `// i18n-ignore`。其他静态检查项见[静态检查约定](../installation/tooling.md#check)。
